# 📚 УУНиТ Дневник · UUST Diary

**Расписание УУНиТ, лекции, домашние задания, экзамены и учебный календарь — в одном приложении. Название на английском: **UUST Diary**.**

## ✨ Возможности

- **Расписание:** загрузка расписания и учебного календаря УУНиТ, выбор группы, просмотр недель и кеш для работы с ранее загруженными данными.
- **Учебные материалы:** лекции, домашние задания, экзамены, заметки и вложения с поддержкой Markdown и предпросмотром.
- **Календарь:** события на дату занятия, учебные недели, отметки выполненных заданий и черновиков.
- **Под себя:** светлая и тёмные темы, масштаб интерфейса, адаптация для телефона.
- **Данные под контролем пользователя:** локальное хранение, импорт и экспорт резервной копии JSON. **Облачной синхронизации между устройствами нет.**

> **Важно:** проект не является официальным приложением УУНиТ. Доступность актуального расписания зависит от внешнего сервиса университета. Личные заметки и вложения сохраняются локально; перед обновлением или переустановкой сделайте экспорт резервной копии.

## 🧩 На чём работает

| Платформа | Технология | Где исходники |
| --- | --- | --- |
| Веб | HTML, CSS, JavaScript; локальный сервер Python | `docs/`, `serve.py` |
| Windows / ПК | Electron, electron-builder | `desktop/`, `assets/` |
| Android | Capacitor 8, Android / Gradle | `android/` |
| Общая сборка | Node.js, esbuild | `scripts/`, `native/` |

**Единый источник веб-интерфейса — `docs/`.** Сборка копирует его в автоматически генерируемую папку `www/` и подключает платформенный мост. Не редактируйте `www/` вручную и не коммитьте её в Git.

## 🚀 Быстрый старт

Понадобится **Node.js 24+** и npm. Из корня проекта:

```bash
npm ci
npm run build
npm test
```

### 🌐 Веб-версия

Понадобится **Python 3.10+**:

```bash
python -m pip install -r requirements.txt
python serve.py
```

Откройте **http://localhost:8000**. Веб-версия читает только локальные опубликованные файлы расписания; сервер нужен для раздачи статики. Просто открывать HTML через `file://` не рекомендуется.

### 🖥️ Windows

Запуск в режиме разработки:

```bash
npm start
```

Сборка установщика **на Windows**:

```bash
npm run desktop:win
```

Результат: `release/UUST-Diary-<версия>-Setup.exe`. Можно также использовать `BUILD-WINDOWS.bat`. Поддерживаются команды `npm run desktop:linux` и `npm run desktop:mac` для соответствующих систем. Установщик Windows по умолчанию **без цифровой подписи**: SmartScreen может показать предупреждение.

### 📱 Android

Нужны **JDK 21**, Android Studio / Android SDK с **Platform 36**. SDK можно настроить через Android Studio; локальный `android/local.properties` не должен попадать в репозиторий.

```bash
npm run android:open
npm run android:apk
```

Первый запуск откроет Android Studio, второй создаст отладочный APK:

`android/app/build/outputs/apk/debug/app-debug.apk`

Debug APK предназначен для тестирования, **не для публикации в Google Play**. Для магазина соберите подписанный release AAB и надёжно храните ключ подписи вне репозитория.

## ✅ Проверки и CI

```bash
npm test
python -m unittest discover -s tests -p 'test_*.py'
```

`npm test` выполняет JS-тесты и пересобирает веб-ресурсы. Python-тесты запускайте отдельно; им нужны зависимости из `requirements.txt`. Информация о ранее выполненных проверках находится в `VALIDATION.md` (это исторический отчёт, не гарантия тестирования текущей версии).

Файл `.github/workflows/build.yml` запускается вручную (**Actions → Build UUST Diary → Run workflow**) или при пуше тега `v*` и создаёт артефакты Windows EXE и Android debug APK. Для обычных пушей и pull request добавлен отдельный workflow с тестами. **Артефакты GitHub Actions не считаются опубликованными релизами GitHub Releases** — их можно скачивать со страницы запуска workflow.

## 🔐 Публичный репозиторий и конфиденциальность

- В Git попадают только исходники и необходимые конфигурации. Каталоги `node_modules/`, `www/`, `release/`, временные Android-сборки и кеши игнорируются.
- **Не добавляйте** `.env`, ключи подписи, токены, `android/local.properties`, персональные JSON-экспорты, дампы БД или установочные `.exe` / `.apk` через `git add -f`.
- Файлы `release/UUST-Diary-Setup.exe` и `release/win-unpacked/УУНиТ Дневник.exe` нужны лишь как локальные результаты сборки, поэтому отсутствуют в исходном архиве и не должны попадать в историю Git. При необходимости публикуйте установщик отдельно через **GitHub Releases**, предварительно проверив его.
- Настройте репозиторий как **Private** для первого пуша, ещё раз проверьте `git status` и `git diff --cached --name-only`, а затем при желании переведите его в Public. Если секрет **уже был закоммичен ранее**, `.gitignore` не удалит его из истории: нужен отзыв секрета и очистка истории.

## Синхронизация устройств в локальной сети

Поддерживаются ПК ↔ ПК, ПК ↔ Android и Android ↔ Android. На обоих устройствах должна быть установлена эта версия приложения.

1. Подключите устройства к одной сети и откройте **Настройки** на обоих.
2. В блоке **Устройства в локальной сети** автоматически появятся другие устройства с открытыми настройками UUST Diary. Текущее устройство в список не включается. Адреса и коды вводить не нужно.
3. Над списком показано число ваших записей, рядом с каждым устройством — число его записей.
4. Нажмите на устройство, которому хотите отправить данные.
5. На получателе появится запрос с именем отправителя и сравнением количества записей. После согласия передаются данные и полностью заменяют содержимое получателя.
6. Отправитель увидит результат: принято или отклонено. Ожидание подтверждения — до двух минут.

В счётчик входят лекции, ДЗ, экзамены и черновики (каждый черновик — отдельная запись). Предметы, пары расписания и вложения не увеличивают этот счётчик, но передаются вместе с данными. Также заменяются выбранная группа, сохранённое расписание и настройки оформления. Новая копия не объединяется со старой. Перед заменой предыдущая база сохраняется локально в IndexedDB под ключом `pre_sync_backup`; для восстановления через интерфейс заранее экспортируйте JSON.

При закрытии настроек или уходе приложения в фон обнаружение выключается. Для обнаружения используется UDP multicast, для передачи — временный локальный HTTP-сервер. Windows может запросить доступ в частной сети: разрешите его приложению. Если устройства не появляются, проверьте, что оба приложения открыты, брандмауэр разрешает связь и Wi-Fi не использует изоляцию клиентов. В список не входят произвольные телефоны, роутеры и устройства без UUST Diary.

Подтверждение требуется на получателе до отправки записей и вложений. Имя устройства и число записей видны другим экземплярам приложения в сети; содержимое не доступно для скачивания. Соединение не шифруется, используйте доверенную сеть. Веб-версия на GitHub Pages не участвует в обнаружении; она по-прежнему читает опубликованные файлы расписания.

## Расписание для GitHub Pages без бэкенда

В настройках есть небольшая кнопка **Скачать данные расписания**. Она собирает все сохранённые группы и недели, включая кэш прошлых запусков, в `snapshot.json`. Личные записи и вложения в этот файл не попадают. Экспорт не скачивает ещё не просмотренные недели.

- На ПК выберите папку `docs/data/schedule` нужного репозитория: файл сохранится туда.
- На Android файл сохраняется в `Documents/UUST-Diary/schedule/snapshot.json`.
- В браузере используется стандартная папка загрузок.

Поместите файл по пути **docs/data/schedule/snapshot.json**, сделайте commit/push и дождитесь публикации GitHub Pages из папки `docs`. При перезагрузке веб-версия автоматически использует JSON как основное расписание. Для отсутствующих недель она покажет нейтральное сообщение. Если JSON ещё не добавлен, используются имеющиеся локальные HTML-файлы из `docs/data/schedule`.

Веб-версия на любом хостинге обращается только к файлам своего сайта: нет запросов к сайту университета, прокси или предупреждений о подключении к ним. ПК и Android продолжают загружать и разбирать официальный сайт как раньше. Публиковать весь архив на GitHub Pages не нужно — обновите файлы проекта и публикуйте `docs`.
